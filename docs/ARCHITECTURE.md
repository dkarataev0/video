## 2. Конвейер

```
видео (iPhone .MOV/HEVC/HDR)
 └─ ffmpeg: поворот, HDR→SDR, ≤1080p, постоянная частота кадров (как в исходнике)
     ├─ ВИДЕО: SCRFD-детектор + ArcFace (InsightFace buffalo_l) на каждом кадре
     │    └─ трекинг (IoU + сходство лица, венгерский алгоритм) → треки
     │        └─ кластеризация треков → «персонажи» (миниатюры в интерфейсе)
     │            └─ рендер по 10-секундным фрагментам:
     │                 сглаженные 5 точек лица (Savitzky–Golay, без задержки)
     │                 → HyperSwap 256 (pixel boost 512) → антимерцание в выровненном пространстве
     │                 → маска: размытый прямоугольник ∩ XSeg (руки/волосы/очки перед лицом)
     │                 → вклейка → GFPGAN 1.4 (смешивание 40 %) → пометка «Создано с помощью ИИ»
     └─ АУДИО: BS-RoFormer (audio-separator) → голос | музыка+шумы
          └─ Silero VAD + эмбеддинги CAM++ + кластеризация → кто когда говорит (правится вручную)
              └─ Seed-VC (zero-shot voice conversion, 44 кГц, с F0) для каждой реплики
                  → громкость как в оригинале → на прежнее место → смешивание с фоном
 └─ ffmpeg: склейка фрагментов без перекодирования + AAC + метаданные «AI-modified» → MP4
```

### Почему так

**Лица.** Проверялись форматы входов/выходов моделей по исходникам FaceFusion 3.x (OpenRAIL-AS):
`hyperswap_1a_256` (256×256, шаблон arcface_128, нормализация 0.5/0.5, на вход — нормированный эмбеддинг ArcFace),
`inswapper_128` (128×128, эмбеддинг через матрицу `emap` из последнего инициализатора графа), GFPGAN 1.4 (шаблон ffhq_512), XSeg (256×256, NHWC).
FaceFusion целиком не используется, потому что он выбирает лицо **покадрово** по сходству с эталоном.
На поворотах головы в профиль сходство падает, и замена «мигает». Здесь идентичность определяется для всего **трека**,
поэтому лицо в профиле получает ту же замену, что и в анфас. Пропуски детекции до 0,25 с заполняются интерполяцией.

**Голос.** Нужно сохранить текст, эмоции, интонацию, паузы и темп. Это задача **преобразования голоса (VC)**, а не синтеза речи (TTS).
TTS перечитывает текст заново и теряет актёрскую подачу. Seed-VC работает в режиме zero-shot, то есть дообучать модель не нужно.
Его кодировщик содержания построен на Whisper (многоязычный), поэтому русский язык поддерживается.
Длина выхода равна длине входа (`length_adjust=1.0`). Режим `f0_condition` + `auto_f0_adjust` переносит интонационный контур исходной речи в регистр нового голоса.
Образец целевого голоса используется до 25 с.

**Синхронизация губ.** Отдельный lip-sync (Wav2Lip/LatentSync) **намеренно не применяется**.
Преобразование голоса не меняет тайминг речи, а заменщик лица сохраняет исходную артикуляцию рта. Поэтому губы уже совпадают с речью.
Перегенерация рта lip-sync-моделями даёт размытие и артефакты зубов, то есть ухудшила бы реализм.

**Разделение звука.** BS-RoFormer (`model_bs_roformer_ep_317_sdr_12.9755`) даёт SDR вокала ≈12,97 дБ, а htdemucs_ft — ≈9 дБ.
Чем чище голос, тем лучше VC и тем меньше «призраков» исходного голоса в фоне.

## 3. Зафиксированные версии (проверены вместе)

torch 2.5.1 / torchvision 0.20.1 / torchaudio 2.5.1 (cu124), transformers 4.46.3, onnxruntime-gpu 1.22.0 (CUDA 12 + cuDNN 9),
insightface 2.1, audio-separator 0.48.0, silero-vad 6.3, gradio 5.50.0, Seed-VC commit `51383ef`.

Подводные камни, найденные при проверке:
* `descript-audio-codec` (зависимость Seed-VC) тянет `descript-audiotools`, а тот фиксирует `protobuf==3.19.6`, что ломает onnx/audio-separator.
  Seed-VC нужен только `dac.nn.quantize`, поэтому два MIT-файла лежат в `third_party/dac_shim`.
* torchvision должен строго соответствовать torch, иначе `transformers` падает на `torchvision::nms`.
* В torch ≥ 2.6 у `torch.load` по умолчанию `weights_only=True`, а чекпойнты Seed-VC рассчитаны на старое поведение. Поэтому используется 2.5.1.
* Новые сборки torchaudio сохраняют звук через torchcodec. Воркер Seed-VC пишет WAV через soundfile.

## 4. Лицензии моделей

| Модель | Лицензия |
|---|---|
| InsightFace buffalo_l (детектор, ArcFace), inswapper_128 | только некоммерческое использование |
| HyperSwap 1a/1b/1c | ResearchRAIL (FaceFusion) |
| GFPGAN 1.4 | Apache-2.0 |
| XSeg | GPL-3.0 (DeepFaceLab) |
| Seed-VC | GPL-3.0 |
| BS-RoFormer (веса) | открытые веса сообщества UVR |
| Silero VAD | MIT |

Итог: решение подходит для личного некоммерческого использования. Коммерческое использование потребует замены моделей с некоммерческими лицензиями.

## 5. Конфиденциальность

* Обработка идёт только на вашей сессии Kaggle. Сторонним сервисам файлы не передаются. Аналитика Gradio и телеметрия HF отключены.
* Данные лежат в `/kaggle/temp/studio`: эта папка не сохраняется в «Output» ноутбука и стирается при остановке сессии.
  Кнопка «Удалить все мои данные» стирает их сразу.
* Ссылка закрыта логином и паролем (пароль случайный и генерируется при каждом запуске).
* Ноутбук Kaggle по умолчанию приватный. Не делайте его публичным, если меняли код и добавляли туда свои файлы.
